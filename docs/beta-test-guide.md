# TACT スモールβテスト実施ガイド（STEP27）

対象: 3〜5名程度のスモールβユーザー。
目的: 「初見ユーザーがTACTを説明なしで使えるか」を観測する。
新機能・新UIはこのガイドに含まない（既存機能をそのまま使ってもらう）。

---

## 1. 最初にβユーザーへ渡す依頼文（これだけ伝える）

> 大学生活で使える生成AIについて、簡単なレポートを作ってみて

これ以外の操作手順は事前に説明しない。ユーザーが自由に触った結果をそのまま観察する。

## 2. ユーザーが行き詰まったときだけ示してよい例（教えすぎない）

正解の操作方法として教え込むのではなく、「こういう頼み方もできる」という一例だけ提示する。

- 「さっきの2章をもっと詳しくして」
- 「最新の情報を追加して」
- 「全体を就活生向けに書き直して」

## 3. 利用状況の確認方法（既存DB・既存スクリプトのみ、新規ログ収集なし）

STEP26で作成した `betaUsageReport.ts` をそのまま利用する。

```
npx tsx betaUsageReport.ts <βテスト開始日時>
```

`<βテスト開始日時>` には、実際にβユーザーへ依頼文を渡した日時をISO 8601形式で指定する
（例: `2026-08-12T00:00:00Z`）。これにより、STEP17〜26の開発テストデータを除外し、
βテスト分だけを集計できる（DBスキーマ変更なし。`conversations.created_at` による絞り込み）。

引数を省略すると、開発テストデータを含む全期間が対象になる。

これにより次が分かる。

- Conversation数
- Turn数（ユーザー発言数）
- Workflow成功/失敗
- 実行時間
- 実行されたAgent
- 部分更新/全体書き直しなど、Turnの種類の内訳

## 4. ユーザーフィードバック（自由記述中心）

実施形態は問わない（口頭ヒアリング・チャット・簡単なフォーム等）。このガイドは質問内容のみを提供する。

1. 最初に何をすればいいか分かりましたか？
2. 生成された結果は期待したものでしたか？
3. 「ここを直して」と頼む体験は自然でしたか？
4. 右側のAgent Team表示は役に立ちましたか？
5. ChatGPT等の他のAIツールとの違いを感じましたか？
6. また使いたいと思いましたか？
7. 一番分かりにくかったところはどこですか？
8. 一番便利だと思ったところはどこですか？

## 5. 開発チーム側の事前準備チェックリスト

- [ ] `betaUsageReport.ts` を実行し、βテスト開始前の時点のConversation件数を控えておく（後で開始日時カットオフの目安にする）
- [ ] βユーザーへ渡すのは「1. 最初の依頼文」だけで、それ以上の操作説明はしない
- [ ] フィードバックの8項目は自由記述を優先し、選択式にしすぎない
